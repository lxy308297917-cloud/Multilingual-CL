# 新 SW 开发集能否预示方案一保护消融的正式结果

这是对**已经冻结、已经测完**的两组训练顺序所做的事后评测设计审计，不用正式测试分数选择新方法、层或超参数。每轮的保护／去保护版使用相同 Base、D2 样本顺序和每矩阵 15% 名额；两轮顺序不同。下表均为保护版减去保护版的差值，翻译与摘要为 corpus chrF++，阅读与指令为百分点。

|任务|seed42 开发|seed42 正式|seed43 开发|seed43 正式|
|---|---:|---:|---:|---:|
|EN→SW 翻译|+0.05|+1.61|−0.63|+1.78|
|SW→EN 翻译|−1.10|+4.49|−0.19|+5.89|
|SW 摘要|+0.48|+0.67|−0.39|−0.08|
|EN 阅读|−0.39|+2.78|+10.55|+3.00|
|EN 指令 prompt strict|+3.52|+2.40|+6.25|+6.84|

两轮的 SW→EN 开发集差值都没有预示正式集上约 4.5–5.9 分的保护收益；seed42 开发集 EN 阅读也未显出正式增益。因此，**不能把当前翻译开发集上一个候选与保护基线近乎持平，解释成正式双向翻译也一定持平**。反过来，正式集的正差也不能拿来调下一方法。开发翻译样本取自原 D2 dev 池，旧训练曾在该池计算验证损失；开发与正式源分布、样本规模和提示词可能不同，现有证据不能识别差异的唯一原因。SW 阅读仍无同任务独立开发集。

下一次方法筛选应事先固定新评测样本和准入门槛，报告 SW 翻译、摘要及 EN 阅读／指令的多任务取舍与逐样本区间；不能只按这一份翻译开发集的 corpus chrF++ 排名升级全长训练。若找不到足够可信的独立开发证据，则不为占 GPU 而训练新变体。该判断只改变**下一实验的证据要求**，不修改当前任何正式测试协议、原始输出或已训练模型。
