# 正式学习率前缀下的 15% 掩码 EMA 复核

**结论：预注册门槛失败，停止 EMA 规则的完整训练与正式测试。** 两组独立从同一 Base 开始、使用相同 seed43 前 2048 个 D2 batch2、相同英语校准与每矩阵精确 15% 元素名额（全模型每步 196,529,312）。两组的学习率均复用正式 22,146 步 cosine 的前缀，warmup 1108 步；实测第 2048 步学习率 `4.9754108595e-5`。这修正了旧探针在 2048 步就将学习率降为零的设计差异，不改动旧结果。

前十次掩码刷新换入率中位数：EMA **5.78%**，动态 **58.78%**；全部刷新分别为 8.66% 与 67.94%。EMA 确实改变了动态选择行为，但没有改善双向翻译；尤其 EN→SW 的逐例差区间低于零。两组 `TRAINING_DONE.json`、权重 SHA256 与 256 条开发输出的哈希均通过核验，峰值显存各约 19.97 GiB；训练耗时 EMA 0.887、动态 0.759 GPU 小时。新增 `eval/DECISION.json` 明确执行训练前冻结的门槛，因此不重复利用正式测试集挑方法，也不继续调 EMA β。

只读 `WEIGHT_CHANGE_AUDIT.json` 逐矩阵与 Base 对比：最终 BF16 值改变的候选元素为 EMA **202,112,918（15.43%）**、动态 **471,903,646（36.02%）**；两组非候选权重均逐位未变。这是训练结束时的值差异，不是历次入选集合的并集或每步实际写回次数。它证实 EMA 使最终权重足迹更集中，却没有带来预设翻译收益。

`LAYER_FOOTPRINT_AUDIT.json` 汇总 28 层×Attention/MLP 的 56 组：EMA 每组最终 BF16 差异 11.76%–17.33%，动态为 30.78%–40.72%，EMA **56 组均更少**。足迹收缩遍及全部组件，不能将 EN→SW 差距归因于某个单独层，也不能用此统计反推应更新的层。

只读逐例审计 `ERROR_QUARTILE_AUDIT.json` 显示，EN→SW 的 128 token 生成上限触顶为 EMA 32/128、动态 20/128；但**双方都未触顶**的 92 条中，EMA 逐例平均仍低 1.57 chrF++。按参考答案长度分成四个各 32 条的区间，EMA 差值均不为正。可见此次差距不能仅解释为少数超长参考或生成截断；这是事后描述，不据此改动门槛或调平滑参数。

旧短日程 EMA 对动态的 EN→SW 逐例差也为负；两轮使用不同开发样本和不同学习率日程，不能拿差值幅度作严格跨轮比较，但方向相符。英语阅读／数学剩余独立诊断池仅各 8 条，本轮因 SW 门槛失败没有启动英语测评。这里只能判断 2048 步的同顺序、同名额训练侧表现，不能证明所有全长 EMA 变体必定失败；目前不值得为这个候选占用 22,146 步完整训练和正式测试资源。
