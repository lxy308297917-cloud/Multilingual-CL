# 2026-10-03 EN→SW 退化诊断结果

**结论：**LP 风险约束分配的 EN→SW 损失在同源、未参与训练的 D2 开发样本中也显著出现；因此不能只归因于正式测评的数据域差异。冻结 LP 表把 75,969,304 个每步名额集中到 56 个模块组中的 17 组，39 组为零；93.88% 的名额落在第 0–8 层。这个集中现象与翻译损失相关，但目前不能认定是唯一因果机制。

## 证据

从 D2 `dev.jsonl` 的 2,501 条 EN→SW 平行句中按参考长度四分位、固定哈希各取 32 条，共 128 条。与正式测试集英文源句的精确规范化重叠为零。四个 seed43 模型用完全相同的 prompt token、贪心生成和最大 128 token，输出、哈希和 GPU 身份在 `outputs/`；样本与生成锁定在 `manifest.json`。源 dev 文件哈希及选择 ID 也在 manifest。

|模型|开发集 corpus chrF++|平均逐句 chrF++|
|---|---:|---:|
|LP 保护|24.47|23.23|
|LP 去保护|26.07|24.84|
|均匀保护|40.52|37.96|
|均匀去保护|40.10|37.78|
|LP 保护 + 均匀保护在 LP 零预算矩阵中的权重|31.22|29.25|

LP 保护相对均匀保护，128 条中 114 条逐句 chrF++ 较低，平均差 -14.73，描述性配对 bootstrap 95% 区间 [-16.88, -12.53]；去保护配对平均差 -12.93，区间 [-15.20, -10.76]。正式固定协议 seed43 的 EN→SW 分别为 LP 保护 16.56、均匀保护 33.04，LP 去保护 17.26、均匀去保护 31.60；正式数值见上一轮的 `FINAL_REPORT_ZH.md`。本开发集数值不是正式分数，也不能与正式测评直接相减。

额外的**只读权重换组诊断**：以 LP 保护模型为底，在内存中仅把 LP 表中零名额的 134 个候选矩阵换成同顺序均匀保护模型对应矩阵，其余权重保持 LP。两个来源 checkpoint 文件都未改动。混合模型的开发集 chrF++ 为 31.22，较 LP 提高 6.75，但仍低于均匀版 9.30；逐句平均变化分别为 +6.02 和 -8.71。这表明“LP 从未更新的矩阵”与退化有关，同时也说明仅补回这些矩阵不足以恢复均匀模型效果。换组改变了总的有效更新范围，且混合权重之间会相互作用；不能从一次换组实验单独归因各模块的作用或把它当作同预算方法对照。

具体错误中，LP 常输出语法上像斯瓦希里语、但与英文原句语义不符的句子；均匀版在同样样本上保留更多语义。逐样本预测和分数见 `PER_SAMPLE.jsonl`。不存在空输出；平均重复三元组比例也低，故此次主要不是停机或简单重复造成的测评假象。

## 研究决策

暂停“直接最大化点估计 T、受 E 风险上限约束”的角点 LP 预算作为新主方法：两个训练顺序的正式结果和这次开发集诊断都显示 EN→SW 大幅损失。撤销效应探针本身此前未通过稳定性检查，也不拿它直接补一张新预算表。

下一项值得做的小规模验证是**预算覆盖的作用**：在不看正式测试集的前提下，用一个事先固定的连续正则项约束预算不能集中在少数模块，与同总名额、同数据顺序、同优化器的均匀短训对照，在另一批未用于本次诊断的开发样本上同时观察 EN→SW、SW 阅读及英语保持。正则强度应由训练侧估计量的不确定性或预注册容量条件决定，不能按正式测评分数挑选。短训若无双语收益就停止，不把卡闲置视为必须启动正式训练的理由。

本轨道五个单卡诊断队列均完成，未启动新训练或新正式测评；无自动重试和开机自启。程序为 `prepare.py`、`generate_dev.py`、`analyze.py`，数值见 `RESULTS.json`、`BUDGET_DIAGNOSTIC.json`。
