# 情景稳健预算 512 步短训结论

**决策：不按当前选择表启动完整 22,146 步训练。** 三组都完成了相同的 512 个 seed43 步骤、339,488 输入 token 和每步 75,969,304 个元素名额；单步真实模型预检、权重哈希、开发集输出哈希均通过。固定在训练前的 128 条独立 EN→SW 开发样本与正式测试集、上一轮诊断样本均无精确源句重叠。

|分配方法|非零模块组|第 0–8 层名额比例|开发集 EN→SW chrF++|训练 GPU 小时|峰值显存 GiB|
|---|---:|---:|---:|---:|---:|
|情景稳健预算 + 元素英语保护|18/56|70.12%|18.63|0.104|10.12|
|原点估计 LP 预算 + 相同保护|17/56|93.88%|17.80|0.098|9.70|
|均匀预算 + 相同保护|56/56|32.14%|19.60|0.187|19.97|

稳健预算相对原 LP，逐句 chrF++ 平均差为 +0.81，描述性配对 bootstrap 95% 区间约 [+0.00, +1.60]；但 128 条中仅 59 条较好、67 条较差。稳健预算相对均匀组平均差 -0.72，区间 [-1.64, +0.10]。这只是短训开发集结果，区间未校正多任务或方法比较。原 LP 在完整训练中出现的大幅 EN→SW 退化，512 步尚未充分形成；因此本短训既不证明稳健法能消除长期退化，也没有显示它优于强基线。

原探测的 8 个 T 值是顺序积累 Adam 动量后的步骤统计，彼此相关，不能当作独立重复样本的置信区间；稳健目标只能解释为最差探测步骤压力测试。选择表将早层名额从 93.88% 降至 70.12%，但依旧集中在 18 个模块，未真正解决模块覆盖问题。具体预算与各窗口代理值见 `ALLOCATION_AUDIT.json`；不能以代理值代替下游结果。

代码和输入身份在 `code/sw_d2_robust_probe/TRAINING_RELEASE.json`、`data/manifest.json`、`eval/EVAL_RELEASE.json`。模型各自的 `TRAINING_DONE.json` 记录 512 步、GPU 小时、峰值显存及最终权重哈希。逐样本输出和配对审计见 `eval/RESULTS.json`、`eval/PER_SAMPLE.jsonl`；协调器 `SERIES_COMPLETE.json` 已记录完成。没有失败自动重跑，也没有正式测评或新完整训练。下一步转向已完成全长 LP 与均匀模型的模块换组诊断，找出翻译差距是否集中由少数模块差异驱动，再决定是否值得提出新的预算规则。
