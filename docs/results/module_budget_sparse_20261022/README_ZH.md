# 等元素预算的模块选择：Attention与MLP三组短训

状态：2026-10-22进行中，尚无新终点下游结论。S-All与S-Attn已启动真实训练；S-MLP等待经核实的空闲GPU。D1增强对齐实验独立继续，两条轨道不混合排名。

问题：固定每步元素更新名额，在全部层中选择Attention、MLP或两者，是否改变SW学习与英语保持的取舍？不预设Attention天然更优，也不把模块选择本身称为方法创新。

## 精确预算

实际读取Qwen2.5-1.5B-Instruct权重形状：28层、Attention112个矩阵共154,140,672元素，MLP84个矩阵共1,156,055,040元素。候选总量1,310,195,712，不含embedding、tied LM head、Norm与bias。

\[
K=\lfloor 0.5\min(N_{Attention},N_{MLP})\rfloor=77,070,336.
\]

|组别|允许写回的位置|候选矩阵数|在本组候选中的比例|每步精确名额|
|---|---|---:|---:|---:|
|S-All|所有层Q/K/V/O、Gate/Up/Down|196|5.88235294%|77,070,336|
|S-Attn|所有层Q/K/V/O|112|50%|77,070,336|
|S-MLP|所有层Gate/Up/Down|84|6.66666667%|77,070,336|

比例的分母是各组候选集合，不能写成全模型比例。各矩阵按参数量分配：先取整数下界，剩余名额按Hamilton最大余数补齐，同余数按原模型层及Q/K/V/O/Gate/Up/Down顺序打破平局。[逐矩阵配额](BUDGET_FROZEN.json)完整保存。历史15%结果仅作历史参考，不能替代本轮S-All。

## 算法与统一条件

- 从同一Base开始，seed42，Aya80%+双向翻译各10%，共享原冻结数据流。4293次更新，1,536,351主输入、599,469主监督Token；长度上限2048，microbatch1、有效batch2。
- 使用原稀疏线逐样本有效答案CE及42465步完整学习率日程的同一前缀，warmup2124、峰值5e-5、weight decay0.01、AdamW beta0.9/0.999、eps1e-8。
- BF16权重、FP32动量。所有196个矩阵计算主任务梯度以保持全局clip=1的定义一致；只有本组允许的矩阵推进动量、选择元素和写回。embedding/head/Norm/bias不求梯度。矩阵中暂未入选的元素仍推进该矩阵的FP32动量，沿用原稀疏机制。
- 分数为原无保护动量规则 `abs(m)/(mean(abs(m))+1e-12)`；更新1、21、41……前刷新mask，稳定按扁平索引打破并列。AdamW含预条件、偏置校正和衰减的完整候选位移，仅在mask内转为BF16写回。
- 没有英语保护、回放、对齐、LoRA、OPD或首尾层选择。仅完成三组，不追加参数扫描。

共同名额不代表实际非零写回、累计位移、覆盖并集或训练成本相等。因此逐步保存这些指标，最终按模块报告相对Base的净位移。mask并集包含被选中但可能因LR0/BF16舍入而没有实际改变的位置，不能称为实际写回并集。

## 已通过的验证

[CPU数值回归](OPTIMIZER_TESTS.json)：新优化器在43次更新中与原无保护实现的BF16权重、FP32动量逐位一致；刷新步1/21/41、mask外零写回、稳定并列选择和位压缩恢复均通过。

[真实Qwen预检](TECHNICAL_DONE.json)：三组均用同一两个最长前缀样本（2030/2007 Token）更新8步，精确K一致，未发现冻结位置或mask并集外变化。S-All、S-Attn、S-MLP的PyTorch分配峰值分别约18.32、9.11、17.06GB（十进制，另记录物理显存）。S-All保存4步后恢复至8步，与连续8步的全部权重、FP32动量、mask、并集、计数和RNG逐位一致。验证后已删除新建的冗余技术权重，只留日志和哈希凭证。

每组保存2146与4293步的完整可恢复模型、优化器、调度位置和RNG。mask/并集以`np.packbits`无损保存，不改变训练精度。恢复入口要求独立输出目录，不覆盖旧运行。

## 评测与预先决定的规则

每组完整终点均新生成同一512条回答：SW阅读64、英语阅读64、EN→SW128、SW→EN128、英语指令128。英语源题中1道已知结构错误，在三组出分前冻结排除评分但保留全部原始回答与原批次；英语有效分母63。共511条计分。阅读内容与格式分开，翻译chrF++，指令保持strict定义；数学评分未验收，本轮不生成也不排名。Base仅复用已验核的同协议缓存。

[冻结协议](PROTOCOL_FROZEN.json)与[评测清单](EVALUATION_DATA_FROZEN.json)在新终点分数前确定。报告三组全部两两比较及相对Base的比较，10000次来源分组配对bootstrap、seed42，不计算混合任务平均分。

S-Attn相对S-All进入下一步讨论的门槛：EN→SW和SW→EN的区间下界分别不低于−1 chrF++点，SW阅读不低于−2 F1点；英语阅读内容正确率区间下界大于0，英语指令strict不低于−2点。小样本区间不确定时如实报告；未显著不同不能写成等效。

如果优势伴随累计路径长度或最终净位移L2低于S-All的80%，先要求另行检验匹配位移强度，不能归因于模块位置。本任务不执行该额外对照。仅有明确证据后才讨论第二seed或子空间，不自动启动。

## 成本、资源与可追溯性

冻结上限：三组训练各4 GPU小时，预检合计1小时，三组终点评测各1.5小时，总新增上限17.5 GPU小时；新增磁盘预算75GB。真实前32步吞吐门槛已通过：S-All估计约75分钟、S-Attn约50分钟（包含预设180秒检查点余量，后续实际时间可能不同）；等待空卡不计GPU时间。

用户随后明确授权“可以用上所有空闲的卡”，本轮使用独立临时资源上限8（本机物理卡数），逐卡核验实际进程、利用率与显存，仍排除已有队列预留。[临时授权记录](RESOURCE_EXCEPTION.json)保留，全局队列默认4不变。最初GPU4分配被守卫安全拒绝，没有CUDA上下文或科学更新；资源重新核验后在GPU5完成全部预检，后来GPU4释放后启动S-Attn。没有终止已有任务。
