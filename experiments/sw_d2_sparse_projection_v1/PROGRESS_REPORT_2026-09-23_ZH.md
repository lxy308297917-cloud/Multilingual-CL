# SW D2 五方法实验进度与阶段结果（2026-09-23）

## 1. 本轮问题与统一协议

本轮只比较参数更新方法。五个新模型都从同一 `Qwen2.5-1.5B-Instruct` Base 独立初始化，使用完全相同的 SW D2 冻结数据、样本顺序和训练预算：

- 数据配比：70% SW FineWeb2、10% SW Aya、10% EN→SW、10% SW→EN；
- 预算：15,360,372 个非 padding 输入 token，12,175,915 个监督 token；
- 长度2048，有效 batch2，22,146 个优化步，seed42；
- AdamW、lr 5e-5、cosine、warmup 5%、weight decay 0.01；
- 评测：SW/EN Belebele、SW/EN XL-Sum、双向翻译、IFEval、正式 GSM8K 5-shot；
- MMLU/G-MMLU继续延期；PPL/NLL仅作训练稳定性和拟合诊断，不进入能力综合。

五个新模型分别为：英语保护动态逐元素稀疏、去保护机制对照、首尾层投影更新、无投影机制对照、同协议FP32优化器密集FFT。历史 D2 FFT 的优化器精度等细节不同，只作为历史参考。严格密集参照已完成训练及语言/IFEval/PPL，当前仅缺正式GSM8K 5-shot。

## 2. 两种新稀疏微调方案的详细设计

### 2.1 先说明“稀疏”的口径

这里的稀疏指**每个优化步实际写回权重的参数子集是稀疏的**，不是稀疏前向传播、稀疏反向计算，也不是LoRA一类只保存增量模块的方法。最终仍保存完整模型权重。

为了避免比例歧义，报告同时使用三个口径：

1. **全模型参数**：Base共有1,543,714,304个唯一参数；输入embedding与LM head共享权重，因此只计一次。
2. **梯度/优化器候选参数**：`requires_grad=True`并维护Adam一阶、二阶矩的参数。候选参数会参与反向传播，未必在当前步真正改变。
3. **每步实际更新参数**：当前掩码选中、最终被写回新值的参数。只有这个口径表示本方法每步的非零权重更新比例。

|方法|候选范围|候选参数|候选/全模型|每步实际更新|候选内比例|每步更新/全模型|
|---|---|---:|---:|---:|---:|---:|
|方案一：英语保护动态逐元素稀疏|28层全部Attention/MLP二维矩阵|1,310,195,712|84.873%|196,529,312|15.000%|12.731%|
|方案一去保护对照|同上|1,310,195,712|84.873%|196,529,312|15.000%|12.731%|
|方案二：首尾层投影行更新|第1–5、23–27层的Attention/MLP矩阵|467,927,040|30.312%|233,963,520|50.000%|15.156%|
|方案二无投影对照|同上|467,927,040|30.312%|233,963,520|50.000%|15.156%|

层编号是Qwen实现中的**零基编号**。方案二只开放10/28层，但候选矩阵内更新50%的完整输出行，所以每步实际更新参数量略高于方案一。动态掩码会改变入选位置，因此12.731%和15.156%都是**单步活跃比例**；整个训练期间曾被更新过的唯一参数并集可能更大。本实验没有维护累计并集位图，不能把单步比例写成全程唯一更新比例。

两种方法都为所有候选参数维护FP32 Adam动量。即使一个候选在当前步未入选，它的目标梯度仍参与一阶、二阶动量更新，以便后续掩码重新判断其价值；但其模型权重本步保持逐位不变，weight decay也不会施加到未入选权重。短跑验证确认未选权重完全不变。模型权重为BF16，候选更新量在FP32中计算，选中位置写回BF16。

### 2.2 共同的候选更新量

对候选权重矩阵 `W`，两个方法先使用相同的AdamW规则形成完整候选更新量：

```text
一阶动量：m_t = 0.9 × m_(t-1) + 0.1 × g_t
二阶动量：v_t = 0.999 × v_(t-1) + 0.001 × g_t²
候选更新：update_t = -learning_rate × m_hat_t / (sqrt(v_hat_t) + 1e-8)
                         - learning_rate × weight_decay × W_t
```

其中：

- `g_t`：当前训练batch对该权重的梯度；
- `m_hat_t`、`v_hat_t`：经过偏差修正的一阶、二阶动量；
- `learning_rate = 5e-5`；
- `weight_decay = 0.01`；
- `update_t`：还没有经过保护、投影或稀疏掩码筛选的完整候选更新。

两个方法的区别，是随后如何决定 `update_t` 中哪些位置真正写回模型。

### 2.3 方案一：英语保护动态逐元素稀疏更新

#### 候选范围

Qwen2.5-1.5B共有28层；每层选择7个二维线性矩阵：Attention的`q_proj`、`k_proj`、`v_proj`、`o_proj`，以及MLP的`gate_proj`、`up_proj`、`down_proj`，合计196个矩阵。embedding/共享LM head、RMSNorm、一维bias及其他非二维参数全部冻结。候选范围占全模型84.873%。

#### 目标收益信号

每一步用当前SW D2训练batch计算目标梯度。优化器为所有候选元素维护Adam一阶动量 `m`，并用 `abs(m)` 表示目标训练方向在该元素上的持续强度。为了避免大矩阵或梯度尺度决定选择，每个矩阵内部单独归一化：

```text
target_strength[i,j] = abs(m[i,j]) / (mean(abs(m)) + 1e-12)
```

`target_strength[i,j]`越大，表示位置`[i,j]`在近期SW D2训练中持续获得较强更新信号。

#### 英语遗忘风险信号

保护版使用与D2训练池分离的英语校准池。校准池包含instruction、reading、math三类，各256条候选；每次固定取11条instruction、11条reading和10条math，共32条。校准梯度通过`autograd.grad`独立计算，不覆盖当前训练batch的`.grad`。

训练第0步以及之后每200步刷新一次英语敏感度。完整22,146步轨迹共有111个不同刷新点。对每个候选元素维护英语梯度平方的指数移动平均：

```text
english_sensitivity_t = 0.9 × english_sensitivity_(t-1)
                        + 0.1 × english_gradient_t²
```

第一次刷新直接使用`english_gradient_0²`。随后在每个矩阵内部用敏感度均值归一化：

```text
normalized_english_sensitivity[i,j]
    = english_sensitivity[i,j] / (mean(english_sensitivity) + 1e-12)

protected_score[i,j]
    = target_strength[i,j] / (1 + normalized_english_sensitivity[i,j])
```

同样的目标强度下，英语敏感度越高，`protected_score`越低，该权重越不容易入选。

这个比值偏好“对SW目标方向持续有用、但英语校准梯度敏感度较低”的元素。保护系数固定为1，没有根据测试结果调参。

#### 动态掩码与实际更新

每20个优化步按上述分数在**每个矩阵内**稳定排序，选择恰好向下取整的前15%元素；完整轨迹共有1,108次掩码选择。稳定排序使分数相同时按矩阵展平位置确定顺序。选中元素应用完整AdamW更新，未选元素不写回。

每步实际更新196,529,312个参数，占候选的14.999997%，占全模型12.730938%。这里不是全局top-15%，而是每个矩阵都有15%预算，避免大矩阵吞掉全部更新额度。

#### 去保护对照

`element_unprotected`保留相同的196个候选矩阵、15%预算、20步刷新、FP32动量、训练数据和顺序，只去掉英语敏感度分母：

```text
unprotected_score[i,j] = target_strength[i,j]
```

因此保护版与去保护版的差异可以解释为英语校准风险项的贡献，而不是更新规模或数据差异。

#### 计算特征与限制

方案一的权重写回是稀疏的，但目标梯度和FP32动量覆盖84.873%的模型参数，所以不会获得同等比例的反向计算或优化器显存节省。保护版还需每200步额外计算32条英语样本对196个矩阵的梯度；这也是其训练用时7.27 GPU小时、高于去保护版5.71 GPU小时的主要原因。

### 2.4 方案二：首尾层内部的结构化投影更新

#### 候选层与结构化单位

方案二只开放零基第1–5层与23–27层，共10层。每层仍包含Attention/MLP的7个矩阵，共70个矩阵、467,927,040个候选参数，占全模型30.312%。其余18层、embedding/LM head、Norm和bias冻结。

稀疏单位不是单个元素，而是**完整输出行**。对形状为`[out_features, in_features]`的矩阵，一个输出行被选中后，该行所有`in_features`权重一起更新。这保留了输出通道结构，也便于把选择解释为通道级更新。

#### 冻结英语输入子空间

训练前从独立英语校准池固定选择256条样本：86条instruction、85条reading、85条math。对每条样本，在每个候选线性模块的输入激活序列中最多均匀取8个位置，因此每个模块累计2,048个激活向量。

对每个模块的输入激活矩阵`X`，使用seed42的秩32随机协方差range finder：

```text
Y = 对所有校准样本求和(X转置 × X × random_matrix)
U = 对Y做QR正交分解后得到的正交基
```

其中：

- `X`的每一行是一个输入token在该线性模块前的激活向量；
- `random_matrix`是形状`[输入维度, 32]`的固定高斯随机矩阵；
- `U`的形状也是`[输入维度, 32]`，表示该模块的秩32英语输入子空间。

70个模块各自拥有一个`U`；基文件在训练前冻结并逐模块哈希，训练过程中不再更新。

#### 对AdamW更新方向做部分投影

每一步先计算候选矩阵完整的AdamW更新`update`，再沿输入维度削弱英语子空间内的分量：

```text
projected_update
    = update - 0.5 × (update × U) × U转置
```

可以把原更新直观地拆成两部分：

```text
update = 英语子空间内分量 + 英语子空间外分量
projected_update = 0.5 × 英语子空间内分量 + 英语子空间外分量
```

所以`projection_alpha = 0.5`的含义是：英语子空间内的更新只保留一半，子空间外的更新完整保留。这里不是完全删除英语相关方向。投影作用在包含weight decay的完整候选AdamW更新上，不只是原始梯度。

#### 动态完整行选择

投影后计算每个输出行的均方更新强度：

```text
row_score[i] = mean(projected_update[i, :]²)
```

即对第`i`个输出行的所有列求平方均值。它与按行RMS排序完全等价。每个矩阵内部选择前50%的输出行，并将这些行的全部列写回。行掩码每20步刷新一次，完整训练轨迹共有1,108次选择。

每步更新233,963,520个参数，正好是边缘层候选的50%，占全模型15.155882%。虽然其全模型每步更新比例略高于方案一，但梯度与FP32动量只覆盖30.312%的模型，所以峰值显存约10.90 GiB，明显低于方案一的约19.97 GiB；训练也更快。

#### 无投影对照

`edge_rows_no_projection`固定相同的10层、70个矩阵、50%完整行预算、20步刷新、数据与优化器，只把`projection_alpha`设为0。其行分数直接来自未投影的AdamW更新。投影版与无投影版之间的差异因此主要检验“削弱英语输入子空间更新”本身的作用。

### 2.5 两种方案的本质差别

|维度|方案一：英语保护逐元素|方案二：首尾层投影行更新|
|---|---|---|
|保护信号|周期性英语梯度平方敏感度|训练前冻结的英语输入激活子空间|
|保护发生位置|进入top-k前降低高风险元素分数|先削弱更新在英语子空间内的分量|
|稀疏粒度|单个权重元素|完整输出行/通道|
|空间范围|全部28层Attention/MLP|首尾10层Attention/MLP|
|掩码|每20步动态刷新|每20步动态刷新|
|每步全模型更新比例|12.731%|15.156%|
|英语保护是否动态|敏感度每200步随当前权重刷新|子空间训练前估计后固定|
|主要额外成本|反复英语校准梯度|一次性秩32子空间估计与每步低秩投影|

方案一尝试在全网络中逐元素寻找“高目标收益、低英语风险”的位置；方案二先用层范围约束减少干预区域，再从更新方向中削弱英语输入子空间分量，并以完整行作为结构化更新单位。二者都没有根据测试集选参数，所有比例、刷新周期、层范围、rank和投影强度都在正式训练前冻结。

在已经完成的四个新方法中，`edge_projected_rows` 是当前最合适的候选：

EN3/Target3是相对Base的三任务相对变化等权平均。EN3含SW→EN翻译，因此可能掩盖单项EN阅读或IFEval下降；最终方法选择必须同时查看上面的原始任务，不能只看聚合值。
